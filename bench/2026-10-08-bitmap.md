Compare main `e2c4c6bf67648a7c200d0354ff25e5f65c417a00` (v0.1.5 header)
with this patch alone, compiled into kvspace-c main
`0e5660c37d5584fe774b1c75d71eca3777115671`. Interpreter and backend sources
are otherwise identical. The previously submitted PR #9 capacity initialization
fix is absent from both variants.

Full kvlang interpreter: `774e5315eff9ec39caa1cd6e9791620811845a9d`, stock
benchmark cases. CPU 24, Intel Xeon Gold 6418H, GCC 14.3.0,
`-O3 -g -DNDEBUG`, blockmalloc v0.1.4, kvspace v0.3.0 frontend.
Nine alternating runs per variant; medians of the fixtures' timed interval
exclude process startup/layout loading. Every run uses a fresh SHM store.

These gains concern allocation-heavy interpreter workloads. The iops control
has an unchanged median; its raw samples are retained in the full experiment.
Use its `main` and `allocator` columns to isolate this patch:
[runner, samples and loaded-library hashes](https://github.com/carsontung666/kvlang/tree/feat/interpreter-hotpaths/bench/experiments/20261008-current-python).
The larger `all` gains also include separate runtime/write patches.

This header-only change preserves shared pool layout and rightmost placement.
It works with pools created by v0.1.5, including optimistic subtree hints;
consuming it in kvspace-c requires rebuilding with this header. The currently
released dependency remains v0.1.5.

## Regression

`tutorial/18_bitmap_oracle.c` uses public allocation/free APIs with synthetic
fragmented root bitmaps. An independent reverse scan supplies expected offsets;
the test compares complete root mutation, allocated sizes and free restoration.
It covers all counts 1–63 and boundaries 0–64, sparse/dense/random words and
small exhaustive patterns. Its optimistic subtree hint exercises the new leaf
rejection with v0.1.5 metadata. All 1,251,900 cases pass with GCC, Clang, the
baseline library and ASan/UBSan.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_C_FLAGS="-I$BLOCKMALLOC_PREFIX/include"
cmake --build build -j
./build/tutorial/18_bitmap_oracle
```

The new test runs directly in `make test` and compiler/macOS CI. Root CTest
enablement and the invalid legacy tutorial03 pool size are handled by the
separate PR #9; this patch does not activate those existing registrations.

Independent review also passed 15,219,555 bitmap cases, 240,000 alloc/free
operations with byte-identical baseline metadata, cross-address persisted pool
handover, 3-process/4-thread full-pattern integrity and 4,959 checks after
reopening a fragmented v0.1.5-created backend store. kvspace-c CTest passes 6/6.
